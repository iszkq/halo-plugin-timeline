# 时间轴

## 简介

为 Halo2 提供时间轴组件、横向/竖向布局，可在编辑器中灵活插入，自动适配深色主题。

## 功能特性

- **时间轴组件**
  - 支持在 Halo2 中以组件形式插入时间轴，适配文章内容区和独立页面。
  - 提供横向 / 竖向两种布局，适合展示个人履历、项目进度、版本更新日志等场景。
  - 自动适配深色 / 浅色主题，无需手动切换。

- **时间轴分组管理**
  - 支持为时间轴条目创建“分组”（例如「个人成长」「项目历程」「版本更新」）。
  - 每个分组可设置显示名称和优先级，用于控制分组在前台展示时的顺序。
  - 后台提供分组管理界面，支持新增、编辑、删除分组。

- **时间轴条目管理**
  - 在后台独立的“时间轴”管理界面中，对条目进行新增、编辑、删除。
  - 每条时间轴记录包含：
    - **时间**：可配置精准到年 / 月 / 日的模糊日期（详见下文）。
    - **标题**：用于前台展示的主标题。
    - **内容**：对该时间节点的详细描述（可选）。
    - **图片**：支持上传图片，用于增强视觉效果。
    - **激活状态**：可标记某些条目为“高亮”，便于用户聚焦关键节点。
    - **关联链接**：可选择 Halo 文章，或填写任意自定义 URL。

- **关联内容与跳转**
  - 可以从已有文章中选择一篇作为“关联文章”，时间轴条目前台点击可跳转至该文章。
  - 也可以填写自定义链接（例如外部站点、文档页），文章与自定义 URL 会自动按优先级处理：
    - 若选择了文章，则使用文章链接；
    - 否则，使用自定义 URL；
    - 若两者都未填写，则不设置链接。

- **前台展示组件（Web Component）**
  - 通过前端 `packages` 下的 Web Component 提供时间轴渲染能力。
  - 使用统一的 API 拉取时间轴数据，自动按时间进行排序和分组。
  - 组件样式可通过自定义 CSS 变量进行主题定制，方便与博客整体风格统一。


## 开发环境

- Java 21+
- Node.js 18+
- pnpm

## 开发

```bash
# 启用插件
./gradlew haloServer
# 开发前端
cd ui
pnpm install
pnpm dev
```

## 构建

```bash
./gradlew build
```

构建完成后，可以在 `build/libs` 目录找到插件 jar 文件。

## 新增功能：模糊日期支持

> 本功能为在原插件基础上的增强能力。

### 1. 支持的日期格式

时间轴条目的“时间”字段现在支持以下三种形式的“模糊日期”：

- **仅年**：`YYYY`  
  例如：`2026`，适用于只需要记录年份的场景（如“开始写博客”“大学毕业”）。
- **年-月**：`YYYY-MM`  
  例如：`2026-02`，适用于只需要精确到月份的场景（如“2026-02 产品 V2.0 上线”）。
- **年-月-日**：`YYYY-MM-DD`  
  例如：`2026-02-10`，适用于需要精确日期的场景。

后台表单会对输入格式进行校验，仅允许上述三种格式之一，避免产生难以理解或无法排序的时间数据。

### 2. 后台管理体验优化

- 原版本使用浏览器原生日期选择器，只能选择完整的年月日，无法表达“只到年”或“只到月”的时间节点。
- 现在改为文本输入框，并增加格式校验规则：
  - 保证必填（必须至少有一个“年”），避免时间轴出现“无时间”的记录。
  - 提示信息会说明支持 `YYYY` / `YYYY-MM` / `YYYY-MM-DD` 三种形式，并在输入格式不正确时给出明确的错误提示。

通过这种方式，既保持了数据的规范性，又给予使用者更大的表达自由度。

### 3. 前台展示与排序行为

- 时间数据在后端仍以字符串形式进行存储，无需数据库结构变更。
- 前台在对时间轴条目进行排序时，继续使用字符串比较：
  - `2024` < `2024-05` < `2024-05-10` < `2025`
  - 这种设计天然兼容仅年、年-月、年-月-日三种格式。
- 在展示层面，组件会原样展示你输入的时间字符串：
  - 输入 `2026` 就显示 `2026`
  - 输入 `2026-02` 就显示 `2026-02`
  - 输入 `2026-02-10` 就显示 `2026-02-10`

这意味着你可以非常自然地构建出类似下列的时间轴：

- `2018`：开始学习编程
- `2020-09`：正式入职第一份开发工作
- `2025-12-31`：完成 V3.0 版本发布

### 4. 向下兼容性说明

- 旧版本中已经存储为 `YYYY-MM-DD` 的时间数据会完全保留，且在新版本中仍然合法。
- 不需要进行任何数据迁移操作，升级插件后即可直接使用模糊日期能力。
- 所有依赖 `date` 字段排序、展示的逻辑都保持不变，仅扩展了可选的日期精度。
